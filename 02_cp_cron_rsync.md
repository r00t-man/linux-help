## 📖 Введение

Команда `cp` известна большинству пользователей Linux как инструмент для **копирования файлов**, но она умеет создавать **версионные резервные копии**, что особенно полезно для системных администраторов и разработчиков.

> [!TIP]
> Версионное копирование позволяет отслеживать историю изменений без установки Git или других систем контроля версий.

---

## 🔑 Основные параметры cp для версионного копирования

| Параметр   | Описание                                                       |
| ---------- | -------------------------------------------------------------- |
| `--backup` | Создаёт резервную копию целевого файла перед его перезаписью.  |
| `--suffix` | Определяет пользовательский суффикс для резервной копии файла. |

> [!IMPORTANT]
> По умолчанию резервные копии получают суффикс `~` (например, `file~`), если пользователь не указал свой.

---

## 🔩 Примеры использования cp

### Простейшее резервное копирование

```bash
cp --backup=numbered /path/to/source/file /path/to/destination/
```

Пример для SSH:

```bash
cp --backup=numbered /etc/ssh/sshd_config /data/backup/
```

Результат:

```
sshd_config.~1~
sshd_config.~2~
...
```

---

### Резервное копирование с пользовательским суффиксом

```bash
cp --backup=numbered --suffix=.bak /path/to/source/file /path/to/destination/
```

Пример:

```bash
cp --backup=numbered --suffix=.bak /etc/ssh/sshd_config /data/backup/
```

Результат:

```
sshd_config.bak.1
sshd_config.bak.2
...
```

> [!TIP]
> Это позволяет легко идентифицировать резервные копии по расширению.

## 📊 Сравнение cp, rsync и scp

| Функция                            | cp             | rsync                              | scp                          |
| ----------------------------------- | -------------- | ----------------------------------- | ----------------------------- |
| Версионное копирование             | ✅ с `--backup` | ✅ с `--backup` и `--suffix`        | ❌ (нет встроенного)          |
| Рекурсивное копирование директорий | ✅ с `-r`       | ✅ с `-a` (архив)                   | ✅ с `-r`                     |
| Передача по сети (через SSH)       | ❌              | ✅ через `ssh` (см. ниже)           | ✅ через `ssh` (см. ниже)     |
| Инкрементное копирование (докачка) | ❌              | ✅ копирует только изменённые файлы | ❌ (перекачивает файл целиком) |
| Автоматизация                      | ✅ через cron   | ✅ через cron                       | ✅ через cron (нужен ключ SSH, см. ниже) |

> [!TIP]
> Используйте `rsync` для резервного копирования больших директорий или передачи на удалённый сервер.

Пример `rsync` с версионностью:

```bash
rsync -av --backup --suffix=".bak" /etc/ssh/sshd_config /data/backup/
```

## ⏰ Автоматизация с cron

Чтобы автоматически создавать версии файлов:

1. Откройте crontab:

```bash
crontab -e
```

2. Добавьте задание, например, ежедневно в 2:00:

```cron
0 2 * * * cp --backup=numbered --suffix=.bak /etc/ssh/sshd_config /data/backup/
```

> [!TIP]
> Можно комбинировать с датой в суффиксе:

```bash
cp --backup=numbered --suffix=".$(date +%F).bak" /etc/ssh/sshd_config /data/backup/
```

Результат: `sshd_config.2025-10-03.bak.1`

## 🔐 Удалённое копирование через SSH: `scp` и `rsync`

Всё выше — это копирование **локально, на той же машине**. Если бэкап нужно унести **на другой сервер**, для этого используют `scp` (просто скопировать файл через SSH) или `rsync` поверх SSH (то же самое, но с версионностью/докачкой изменений).

### 🔑 Синтаксис удалённого пути — то, что чаще всего путает новичков

И `scp`, и `rsync` (при передаче по сети) используют один и тот же формат адреса:

```
пользователь@хост:/путь/на/удалённой/машине
```

- `пользователь` — под каким логином заходим по SSH на удалённый сервер (если не указать — используется текущий локальный логин)
- `хост` — IP или имя сервера
- всё после `:` — путь **на удалённой машине**, не на локальной

Направление копирования определяется порядком аргументов: `источник назначение` — как в обычном `cp`. Значит:

```bash
# ЛОКАЛЬНЫЙ файл → НА удалённый сервер
scp /etc/ssh/sshd_config admin@192.168.10.50:/data/backup/

# С удалённого сервера → НА локальную машину (аргументы просто меняются местами)
scp admin@192.168.10.50:/data/backup/sshd_config /etc/ssh/sshd_config.restored
```

### 📋 Примеры `scp`

**Скопировать один файл на удалённый сервер:**
```bash
scp /etc/ssh/sshd_config admin@192.168.10.50:/data/backup/
```

**Скопировать директорию целиком (рекурсивно, флаг `-r` обязателен для директорий):**
```bash
scp -r /etc/nginx admin@192.168.10.50:/data/backup/
```

**Нестандартный порт SSH** (если сервер слушает не 22, а например 2222 — обратите внимание, у `scp` это `-P` заглавная, у обычного `ssh`/`rsync` — строчная `-p`, это частая опечатка):
```bash
scp -P 2222 /etc/ssh/sshd_config admin@192.168.10.50:/data/backup/
```

**Через конкретный приватный ключ** (если ключей несколько или дефолтный `~/.ssh/id_rsa` не подходит):
```bash
scp -i ~/.ssh/id_backup /etc/ssh/sshd_config admin@192.168.10.50:/data/backup/
```

**Скачать файл С удалённого сервера себе:**
```bash
scp admin@192.168.10.50:/etc/ssh/sshd_config ./sshd_config.from-remote
```

> [!NOTE]
> Полный разбор всех опций `scp` (сжатие `-C`, подробный вывод `-v` и т.д.) и разница со сравнением `cp`/`rsync`/`scp` — в статье [📂 Руководство по копированию файлов: rsync, cp, scp](/a/03_copy_advanced).

### 📋 Пример `rsync` поверх SSH

`rsync` умеет то же самое, что `scp`, но передаёт только изменённые куски файлов (быстрее при повторных запусках) и поддерживает `--backup`/`--suffix` даже при передаче по сети:

```bash
rsync -av --backup --suffix=".$(date +%F).bak" /etc/nginx/ admin@192.168.10.50:/data/backup/nginx/
```

> [!WARNING]
> Обратите внимание на **слэш в конце пути источника** — это классическая ловушка `rsync`:
> - `/etc/nginx/` (со слэшем) → копирует **содержимое** папки nginx внутрь `backup/nginx/`
> - `/etc/nginx` (без слэша) → создаст на удалённой машине `backup/nginx/nginx/` (вложенную папку внутри папки)
>
> Путь назначения (после `:`) слэш на конце не требует — на него это правило не влияет.

Нестандартный порт SSH для `rsync` задаётся через `-e` (строчная `-p`, не заглавная, как у `scp`):
```bash
rsync -av -e "ssh -p 2222" /etc/nginx/ admin@192.168.10.50:/data/backup/nginx/
```

### ⏰ Важно для cron: без пароля passwordless-доступ обязателен

`scp`/`rsync` по SSH в интерактивном режиме спросят пароль — а `cron` не умеет вводить пароли за вас, задание просто зависнет или упадёт с ошибкой аутентификации. Чтобы автоматическое копирование в crontab реально работало, нужен **вход по ключу без пароля**:

```bash
# 1. Сгенерировать ключ (один раз, если ещё нет ~/.ssh/id_rsa)
ssh-keygen -t ed25519

# 2. Скопировать публичный ключ на удалённый сервер
ssh-copy-id admin@192.168.10.50

# 3. Проверить, что вход теперь БЕЗ запроса пароля
ssh admin@192.168.10.50 "echo ok"
```

Только после этого можно смело класть `scp`/`rsync`-команду в `crontab -e` — она отработает в фоне без чьего-либо участия.

## 💡 Дополнительно

* Рекурсивное копирование директорий:

```bash
cp -r --backup=numbered /etc/nginx /data/backup/
```

* Интеграция с `rsync` для удалённых серверов (формат адреса и слэш в конце пути — см. раздел [Удалённое копирование через SSH](#-удалённое-копирование-через-ssh-scp-и-rsync) выше):

```bash
rsync -av --backup --suffix=".$(date +%F).bak" /etc/nginx/ admin@192.168.10.50:/data/backup/nginx/
```

* Используйте `--verbose` для подробного вывода:

```bash
cp -v --backup=numbered /etc/ssh/sshd_config /data/backup/
```
