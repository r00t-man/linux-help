# 🖥 Гайд по мониторингу и отладке Linux

В этой инструкции вы найдёте подробное описание основных команд мониторинга процессов, ресурсов системы, журналов и отладки в Linux.

---

## ⚡ 1. Мониторинг процессов

### `top` — процессы в реальном времени
```bash
top
```

* Отображает процессы с автоматическим обновлением.
* Полезные клавиши:

  * `M` — сортировка по памяти
  * `P` — сортировка по CPU
  * `T` — сортировка по времени
  * `k` — отправка сигнала процессу
  * `q` — выход

> [!TIP]
> Для более удобного интерфейса можно использовать `htop` — отдельный пакет, не входит в базовую систему:
> ```bash
> sudo apt install htop   # Astra Linux
> sudo yum install htop   # РЕД ОС (или dnf)
> ```

---

### `ps` — снимок процессов

```bash
ps -eafw
ps -e -o pid,args --forest
```

* `-eafw` — все процессы, полная информация, широкий вывод
* `--forest` — отображение в виде дерева

### `pstree` — дерево процессов

```bash
pstree -p
```

* Показывает процессы в виде дерева с PID.

## 🖥 2. Управление процессами

### `kill` — отправка сигналов

```bash
kill -9 98989        # SIGKILL, насильственное завершение
kill -TERM 98989     # SIGTERM, корректное завершение
kill -HUP 98989      # перечитать конфигурацию (см. предупреждение ниже)
```

> [!IMPORTANT]
> `SIGKILL` завершает процесс немедленно, данные могут быть потеряны. Используйте его только при необходимости.

> [!WARNING]
> "SIGHUP = перечитать конфиг" верно ТОЛЬКО для демонов, которые сами так решили это обрабатывать (nginx, sshd, rsyslog и подобные — так принято по конвенции, не гарантия). Для процесса, который не перехватывает `SIGHUP` специально, действие по умолчанию — **завершение процесса** (исторически сигнал означал "разрыв соединения с управляющим терминалом"). Не отправляйте `-HUP` вслепую произвольному процессу в расчёте на "перечитает конфиг" — сначала проверьте, что именно эта программа так делает (обычно написано в её `man`).

## 💾 3. Файлы и ресурсы процессов

### `lsof` — открытые файлы

Если команда не найдена — отдельный пакет:
```bash
sudo apt install lsof   # Astra Linux
sudo yum install lsof   # РЕД ОС (или dnf)
```

```bash
lsof -p 98989       # файлы процесса
lsof /home/user1    # файлы в директории
```

* Помогает находить зависшие файлы, сокеты и блокировки.

## ⚙️ 4. Отладка системных вызовов

### `strace`

```bash
strace -c ls > /dev/null
strace -f -e trace=openat,open ls > /dev/null
```

* `-c` — статистика вызовов
* `-f` — дочерние процессы
* `-e trace=...` — фильтр вызовов по имени

> [!WARNING]
> Проверено вживую: на современных ядрах/glibc реальные вызовы открытия файлов почти всегда идут через **`openat`**, а не старый `open` — фильтр `-e open` (без `openat`) на такой системе покажет **пустой вывод**, хотя `ls` совершенно точно открывает файлы. Указывайте оба варианта (`trace=openat,open`), если не уверены, какой именно использует конкретная программа/библиотека.

## 📄 5. Мониторинг в реальном времени

### `watch`

```bash
watch -n1 'cat /proc/interrupts'
```

* Запуск команды каждые `n` секунд

### `last`

```bash
last reboot
last user1
```

* История перезагрузок и входов пользователей

## 💽 7. Диагностика дисков

### `smartctl`

Отдельный пакет, не входит в базовую систему:
```bash
sudo apt install smartmontools   # Astra Linux
sudo yum install smartmontools   # РЕД ОС (или dnf)
```

Сначала узнайте реальное имя диска — `/dev/hda` устарело (это старая IDE-нумерация, на любом современном ядре такого устройства просто нет):
```bash
lsblk -d -o NAME,TYPE
```

```bash
smartctl -A /dev/sda      # обычный SATA/SAS/виртуальный диск
smartctl -i /dev/sda
smartctl -a /dev/nvme0n1  # NVMe-накопитель — обычно отдельное имя, не /dev/sdX
```

* Проверка состояния HDD/SSD через SMART

## 📄 8. Журналы системы

### `tail`

```bash
tail -f /var/log/messages   # РЕД ОС (RHEL-семейство) — стандартный путь
tail -f /var/log/syslog     # Astra Linux (Debian/rsyslog) — эквивалент здесь называется иначе
tail /var/log/dmesg
```

> [!NOTE]
> `/var/log/messages` и `/var/log/syslog` — это два РАЗНЫХ файла на двух РАЗНЫХ семействах ОС, не опечатка и не взаимозаменяемость: РЕД ОС/RHEL пишет общий системный лог в `messages`, Astra/Debian — в `syslog`. Файла с "чужим" именем на конкретной системе просто не будет.

### `journalctl`

```bash
journalctl
journalctl -b
journalctl -u ssh     # Astra Linux — юнит называется "ssh"
journalctl -u sshd    # РЕД ОС — юнит называется "sshd" (то же различие, что и в статье про NTP: ntp/ntpd)
journalctl -f
journalctl -p err
journalctl --since "2025-10-01" --until "2025-10-02"
```

> [!TIP]
> Для поиска ошибок используйте (имя юнита — своё для каждой ОС, см. выше):

```bash
journalctl -u ssh | grep "Failed"    # Astra
journalctl -u sshd | grep "Failed"   # РЕД ОС
```
