# 📝 Настройка истории команд Bash

Bash хранит историю всех введённых команд **в памяти** текущей сессии и сбрасывает её в файл `~/.bash_history` только при штатном выходе из сессии (или командами `history -a`/`-w`, см. ниже).
Просмотреть текущую историю:

```bash
history
```

> [!IMPORTANT]
> **Все** настройки ниже (`export ...`, `shopt -s ...`, `PROMPT_COMMAND=...`) работают только **в той сессии, где вы их ввели**. Если ввести команду прямо в терминале и не добавить её в `~/.bashrc` — после перезагрузки сервера или открытия новой сессии/терминала настройка исчезнет, как будто её и не было. Это самая частая причина жалобы "настройки сбрасываются" — их не забыли **сохранить**, а только опробовали вручную.

Правильный порядок для любой настройки из этой статьи:

```bash
nano ~/.bashrc
# добавить нужную строку (export ... / shopt -s ...) в конец файла, сохранить
source ~/.bashrc   # применить немедленно, не открывая новую сессию
```

**Как проверить, что настройка реально сохранилась** (а не только сработала в текущей сессии):
```bash
exit
# зайти заново (новый SSH-сеанс или новый терминал)
echo $HISTTIMEFORMAT $HISTSIZE   # должно вывести то, что вы задали, а не пусто/дефолт
```
Если после нового входа значения снова дефолтные — смотрите раздел [Если настройки всё равно сбрасываются](#-если-настройки-всё-равно-сбрасываются) в конце статьи.

## 📦 Готовый комплект (минимум): время + история на 10000 + надёжное сохранение

Если нужно быстро включить сразу три вещи из этой статьи (дата/время в `history`, увеличенный размер истории, мгновенное и безопасное сохранение новых команд) — добавьте в конец `~/.bashrc` целиком:

```bash
export HISTTIMEFORMAT="%Y-%m-%d %H:%M:%S "
export HISTSIZE=10000
export HISTFILESIZE=10000
shopt -s histappend

if [ -z "$PROMPT_COMMAND" ]; then
    PROMPT_COMMAND='history -a'
else
    PROMPT_COMMAND="$PROMPT_COMMAND; history -a"
fi
```

Затем:
```bash
source ~/.bashrc
```

> [!TIP]
> Блок с `if`/`else` — это **безопасная** версия настройки из раздела 4 ниже: сам проверяет, была ли переменная `PROMPT_COMMAND` уже занята чем-то другим, и правильно дописывает `history -a` в обоих случаях. Почему это важно и какая именно ошибка возникает без такой проверки — разобрано ниже, в разделе 4.

Подробное объяснение каждого пункта — в разделах 1–4 ниже.

## ⚡ 1. Отображение даты и времени выполнения команд

По умолчанию история показывает только номера и команды.
Для удобного отслеживания времени выполнения, добавьте в `~/.bashrc`:

```bash
export HISTTIMEFORMAT="%h %d %H:%M:%S "
```

После этого команда `history` будет отображать дату и время:

```
113 Jun 08 16:31:06 sudo ifconfig
114 Jun 08 16:31:10 top
115 Jun 08 16:31:19 ping disnetern.ru
116 Jun 08 16:31:22 history
```

> [!TIP]
> `%h` — месяц, `%d` — день, `%H:%M:%S` — часы, минуты и секунды.
> Можно настроить формат по своему усмотрению, например `"%Y-%m-%d %H:%M:%S "`.

## 🛠 2. Увеличение размера истории

Bash по умолчанию хранит ограниченное количество команд (обычно 500).
Для увеличения количества команд в памяти и в файле истории, добавьте в `~/.bashrc`:

```bash
export HISTSIZE=5000       # Количество команд в памяти
export HISTFILESIZE=5000   # Максимальное количество строк в файле ~/.bash_history
```

> [!TIP]
> Можно установить любое значение, в зависимости от потребностей.

---

## 🧩 3. Добавление новых команд в файл истории

По умолчанию Bash перезаписывает `~/.bash_history` при выходе из сессии.
Чтобы команды добавлялись в файл, а не перезаписывали его, включите опцию `histappend` — **добавьте в `~/.bashrc`**:

```bash
shopt -s histappend
```

> [!IMPORTANT]
> Это предотвращает потерю истории при одновременных нескольких терминальных сессиях. Как и остальные настройки — работает только если строка добавлена в `~/.bashrc`, а не введена один раз в терминале (иначе после закрытия сессии `histappend` снова выключен по умолчанию).

## ⏱ 4. Мгновенное сохранение истории команд

По умолчанию история команд сохраняется только при завершении сессии.
Если сессия внезапно оборвется, текущая история может быть потеряна.

Чтобы сохранять команды сразу после их выполнения, используйте переменную `$PROMPT_COMMAND` — **как и всё остальное, добавьте нужную строку в `~/.bashrc`**, иначе после закрытия терминала настройка исчезнет:

### Безопасный вариант — с проверкой, была ли переменная уже занята

```bash
if [ -z "$PROMPT_COMMAND" ]; then
    PROMPT_COMMAND='history -a'
else
    PROMPT_COMMAND="$PROMPT_COMMAND; history -a"
fi
```

* `history -a` — добавляет команды текущей сессии в файл `~/.bash_history` сразу после выполнения.
* `[ -z "$PROMPT_COMMAND" ]` — проверяет, пуста ли переменная (то есть ничем ещё не занята). Если да — просто задаём `history -a`. Если там уже что-то есть (например, другой инструмент/фреймворк уже что-то туда прописал) — дописываем через `;`, ничего не затирая.
* В ветке `else` используются **двойные** кавычки (`"$PROMPT_COMMAND; history -a"`) — значение подставляется здесь и сейчас, один раз, результат сохраняется как обычная строка. Это специально не тот приём с одинарными кавычками, что можно встретить в старых гайдах (`PROMPT_COMMAND='$PROMPT_COMMAND; history -a'`) — см. предупреждение ниже, почему это разные вещи.

> [!WARNING]
> Проверено вживую (`set -x` + принудительный вызов `eval "$PROMPT_COMMAND"`, как это делает сам bash перед каждым приглашением): старый приём с одинарными кавычками — `PROMPT_COMMAND='$PROMPT_COMMAND; history -a'` — **ломается, если переменная до этого не была задана**. Ошибка на каждый prompt: `bash: $PROMPT_COMMAND;: command not found`. Причина: одинарные кавычки сохраняют строку `$PROMPT_COMMAND; history -a` буквально; когда bash её выполняет, `$PROMPT_COMMAND` разворачивается в ЭТУ ЖЕ строку целиком (а не в пусто), и получившийся текст `$PROMPT_COMMAND; history -a; history -a` bash воспринимает как попытку запустить несуществующую команду с именем `$PROMPT_COMMAND;`. Если же переменная УЖЕ содержала рабочую команду до этой строки — трюк с одинарными кавычками работает нормально (именно поэтому "сработало на одном сервере" и не сработало бы гарантированно на другом, где `PROMPT_COMMAND` изначально пуст). Вариант с `if`/`else` и двойными кавычками выше корректен в обоих случаях — используйте его.

## 🔍 5. Дополнительные советы

* Используйте `history | grep <команда>` для поиска конкретной команды в истории.
* Для немедленного сохранения всей истории выполните:

```bash
history -w
```

* Для загрузки истории из файла в текущую сессию:

```bash
history -r
```

* Настройка `HISTCONTROL=ignoredups:erasedups` помогает избежать повторяющихся команд (добавить в `~/.bashrc`, как и остальное):

```bash
export HISTCONTROL=ignoredups:erasedups
```

* Добавьте `ignorespace`, если хотите иметь возможность **не записывать** в историю отдельную команду (например с паролем в аргументе) — набирайте её с одного пробела в начале строки:

```bash
export HISTCONTROL=ignoredups:erasedups:ignorespace
```
```bash
 mysql -u root -pSuperSecret123   # начинается с пробела — в history не попадёт
```

> [!TIP]
> Сочетание всех этих настроек делает историю Bash максимально информативной и защищает от её потери при аварийном завершении терминала.

## 🚫 Если настройки всё равно сбрасываются

Если строки добавлены в `~/.bashrc` (не просто введены в терминал), но после перезагрузки/новой сессии всё равно видите значения по умолчанию — проверяйте по порядку:

1. **Правите не тот `~/.bashrc`.** Частый случай: настройки правили под своим пользователем, а реально работаете под `root` (через `sudo -i` или `su -`) — у root **свой отдельный** `/root/.bashrc`, изменения обычного пользователя туда не попадают. Проверьте, под кем реально сидите: `whoami`, и правьте `.bashrc` именно этого пользователя.

2. **Заходите не login-оболочкой, в которой `~/.bashrc` вообще не читается.** `~/.bashrc` читается для *интерактивных не-login* шеллов. При SSH-подключении обычно запускается *login*-шелл, который читает `~/.bash_profile`/`~/.profile` — если в нём нет строки, которая подключает `~/.bashrc` (обычно что-то вроде `[ -f ~/.bashrc ] && . ~/.bashrc`), ваши правки в `~/.bashrc` при SSH-входе не сработают вовсе. Проверьте:
   ```bash
   grep bashrc ~/.bash_profile ~/.profile 2>/dev/null
   ```
   Если пусто — добавьте туда `source ~/.bashrc` вручную.

3. **Системный конфиг перезаписывает пользовательский.** `/etc/bash.bashrc` (Astra/Debian) или `/etc/bashrc` (РЕД ОС/RHEL-семейство), а также скрипты в `/etc/profile.d/*.sh` могут задавать те же переменные и выполняться **после** вашего `~/.bashrc` (порядок зависит от того, что именно и куда подключает конкретный дистрибутив). Проверьте, нет ли там того же имени переменной:
   ```bash
   grep -n "HISTSIZE\|HISTTIMEFORMAT\|PROMPT_COMMAND\|histappend" /etc/bash.bashrc /etc/bashrc /etc/profile.d/*.sh 2>/dev/null
   ```

4. **Переменная залочена политикой аудита (`readonly`).** На некоторых защищённых сборках (в т.ч. сертифицированных под требования ИБ) `HISTSIZE`/`HISTFILESIZE` намеренно делают неизменяемыми, чтобы пользователь не мог урезать журнал команд. В этом случае `export HISTSIZE=...` выдаст явную ошибку `bash: HISTSIZE: readonly variable` — если видите её, значит ограничение стоит намеренно, обходить его не нужно без согласования с ИБ. Проверить:
   ```bash
   readonly -p | grep -i hist
   ```
