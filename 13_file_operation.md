# 📂 Основные операции с файлами в Linux

---

## 🧭 Введение

Работа с файлами — базовая часть администрирования Linux.
Здесь собраны самые часто используемые команды: от просмотра содержимого каталогов до безопасного удаления и создания ссылок.

---

## 📜 1. Просмотр содержимого каталога — `ls`

```bash
ls -l /etc
```

**Ключи:**

* `-l` — длинный формат (разрешения, владелец, размер, дата);
* `-a` — показывает скрытые файлы (начинающиеся с `.`);
* `-h` — человекочитаемые размеры (например, 1K, 2M, 3G);
* `-t` — сортировка по времени изменения.

📘 **Примеры:**

```bash
ls -lah /var/log
ls -lt /home/user
```

> [!TIP]
> Комбинируйте опции: `ls -alh` — один из самых часто используемых вариантов.

---

## 📦 2. Копирование файлов — `cp`

```bash
cp source.txt /backup/source.txt
```

**Основные опции:**

* `-r` — рекурсивное копирование каталогов;
* `-p` — сохраняет права, дату и владельца;
* `-i` — спрашивает подтверждение при перезаписи;
* `--backup=numbered` — создаёт версии файлов (пример в отдельной статье);
* `-v` — показывает процесс копирования.

📘 **Примеры:**

```bash
cp -r /etc/nginx /backup/nginx_config/
cp -pv myfile.txt /tmp/
```

> [!TIP]
> Для регулярного копирования удобно использовать `rsync` — он быстрее и поддерживает синхронизацию.

---

## 🔁 3. Перемещение и переименование — `mv`

```bash
mv oldname.txt newname.txt
```

**Опции:**

* `-i` — подтверждение при перезаписи;
* `-v` — отображает выполняемые действия.

📘 **Примеры:**

```bash
mv -v /tmp/test.txt /home/user/docs/
mv -i config.old config.bak
```

> [!NOTE]
> Команда `mv` используется и для **переименования**, и для **перемещения**.

---

## 🗑️ 4. Удаление файлов — `rm`

```bash
rm filename.txt
```

**Опции:**

* `-i` — подтверждение для каждого файла;
* `-r` — рекурсивное удаление каталогов;
* `-f` — принудительное удаление (без вопросов);
* `-v` — показывает процесс удаления.

📘 **Примеры:**

```bash
rm -i important.txt
rm -rf /tmp/old_logs/
```

> [!WARNING]
> ⚠️ `rm -rf /` — **не выполняй никогда**! Это удалит всё с диска.
> Используй `trash-cli` для безопасного удаления (перемещает в корзину) — пакет отдельный, не входит в базовую систему:
> ```bash
> sudo apt install trash-cli   # Astra Linux
> ```
> Затем команда `trash` кладёт файл в корзину вместо удаления (`trash file.txt`). На РЕД ОС пакет с таким именем в стандартных репозиториях может отсутствовать (это Python-утилита из Debian-мира) — проверяйте `yum search trash-cli`/`dnf search trash-cli` на конкретной машине, не считайте доступность само собой разумеющейся.

## 🔗 5. Создание ссылок — `ln`

**Жёсткая ссылка:**

```bash
ln original.txt copy.txt
```

**Символическая ссылка (ярлык):**

```bash
ln -s /etc/nginx/nginx.conf ~/nginx.conf
```

📘 **Разница:**

* Жёсткая ссылка (`ln`) — копия указателя на тот же файл;
* Символическая (`ln -s`) — ссылка на путь, как «ярлык» в Windows.

> [!IMPORTANT]
> У жёсткой ссылки два практических ограничения, из-за которых новички часто получают непонятную ошибку:
> - **Нельзя создать между разными разделами/файловыми системами** — только в пределах одного раздела (ошибка `Invalid cross-device link`, если пробовать между, например, `/` и отдельно смонтированным `/home`).
> - **Нельзя создать на директорию** (без специальных прав root и то не везде) — ошибка `hard link not allowed for directory`/`Is a directory`. Для ссылок на папки годится только символическая (`ln -s`).
>
> Символическая ссылка обоих ограничений не имеет — работает между разделами и на директории тоже, поэтому на практике `ln -s` используют значительно чаще.

> [!TIP]
> Символические ссылки удобны для коротких путей к часто используемым конфигам или скриптам.

## 🔒 6. Безвозвратное удаление — `shred`

```bash
shred -u -v -n 3 secret.txt
```

**Опции:**

* `-u` — удалить после перезаписи;
* `-v` — показывать процесс;
* `-n 3` — количество проходов (по умолчанию 3).

📘 **Пример:**

```bash
shred -u -n 5 ~/Documents/passwords.txt
```

> [!IMPORTANT]
> `shred` полезен при удалении конфиденциальных данных с HDD.
> ⚠️ На SSD эффективность ниже из-за особенностей контроллера памяти (wear leveling — реальные перезаписываемые ячейки физически не те же самые, что логический адрес файла).

> [!WARNING]
> Ещё важнее для реального использования (пример в статье — `passwords.txt`, это не абстрактный случай): **`shred` не гарантирует затирание на журналируемых и copy-on-write файловых системах** — это написано прямо в официальном мануале `shred`. На **ext4 с журналированием метаданных** (режим по умолчанию) есть шанс, что старые данные останутся в журнале ФС даже после `shred` самого файла. На **Btrfs** (copy-on-write) и подобных — `shred` практически бесполезен, ФС физически не перезаписывает старые блоки на месте. Для файловой системы в целом надёжнее шифрование диска (LUKS) с самого начала, чем `shred` постфактум одного файла — если данные реально чувствительные, не полагайтесь на `shred` как на единственную меру.

## 🧰 7. Дополнительные полезные команды

### 📄 `cat`, `tac`, `less`, `head`, `tail`

| Команда           | Назначение                     | Пример                      |
| ----------------- | ------------------------------ | --------------------------- |
| `cat file.txt`    | показать содержимое            | `cat /etc/hostname`         |
| `tac file.txt`    | показать наоборот              | `tac /var/log/syslog`       |
| `head -n 10 file` | первые 10 строк                | `head -n 20 /etc/passwd`    |
| `tail -f file`    | последние строки с обновлением | `tail -f /var/log/messages` |
| `less file`       | просмотр с прокруткой          | `less /etc/services`        |

> [!TIP]
> `tail -f` незаменим при мониторинге логов в реальном времени.

---

### 🧾 `stat` — информация о файле

```bash
stat /etc/passwd
```

Показывает права, владельца, дату доступа, изменения и модификации.

---

### 🧩 `file` — определение типа файла

```bash
file /bin/bash
# /bin/bash: ELF 64-bit LSB executable
```

---

### 🔍 `find` и `locate` — поиск файлов

**Примеры:**

```bash
find /etc -name "*.conf"
locate nginx.conf
```

> [!NOTE]
> `locate` не входит в базовую систему — нужно поставить пакет с индексом файлов:
> ```bash
> sudo apt install plocate    # современный вариант (Astra 1.8+); если недоступен — sudo apt install mlocate
> sudo yum install mlocate    # РЕД ОС (или dnf)
> ```
> `find` ищет по диску в реальном времени (всегда актуально, но медленнее), `locate` — по заранее собранному индексу (мгновенно, но не увидит файлы, появившиеся после последнего `updatedb`).

> [!TIP]
> После установки `locate` нужно обновить базу (и затем периодически, обычно это уже делает cron автоматически раз в сутки):
>
> ```bash
> sudo updatedb
> ```

---

### ⚙️ `touch` — создание пустого файла или обновление даты

```bash
touch newfile.txt
```

> [!NOTE]
> Если файл `newfile.txt` уже существует — содержимое **не стирается**, обновляется только время доступа/модификации (см. <a href="/a/07_file_timestamps">Временные метки файлов</a>). Файл создаётся пустым только если его ещё не было.

---

### 🧹 `du` и `df` — анализ дискового пространства

```bash
du -sh /var/log/*
df -h
```

## 🧠 Комбинирование команд

📘 **Пример:**
Скопировать все `.conf` файлы из `/etc` в `/backup`, сохранив структуру каталогов.

```bash
find /etc -name "*.conf" -exec cp --parents {} /backup \;
```

📘 **Пример:**
Удалить все `.tmp` файлы старше 7 дней:

```bash
find /tmp -type f -name "*.tmp" -mtime +7 -delete
```

## 🚀 Заключение

Эти команды покрывают **90%** ежедневных задач по управлению файлами в Linux.
Регулярная практика и понимание опций помогут работать быстрее, безопаснее и эффективнее.

---

> [!TIP]
> Создай себе шпаргалку:
>
> ```bash
> alias ll='ls -alh'
> alias rm='rm -i'
> alias cp='cp -iv'
> ```
>
> Добавь эти строки в `~/.bashrc` для автоматического применения.

> [!WARNING]
> Алиас на `rm -i` защищает только **интерактивный ввод в терминале тем же пользователем**. Он НЕ сработает: в скриптах и cron-заданиях (алиасы там не разворачиваются, только в интерактивном шелле), при вызове полным путём (`/usr/bin/rm ...` — алиас применяется только к голому имени команды), и под `root` через `sudo`, если у root нет ровно такого же алиаса в его собственном `.bashrc`. Не полагайтесь на алиас как на единственную защиту от случайного `rm -rf` — он снижает риск при ручной работе, но не гарантия для автоматизации.
